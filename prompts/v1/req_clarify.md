**全局评分原则**：需求优于或等于基准SRS是可接受的，应给予正向评分（+1或+2）。需求劣于基准SRS是不可接受的，应给予负向评分（-1或-2）。

评分规则（5级评分，基于需求与基准SRS的符合程度）：
+2: 完全符合 - 需求与基准SRS完全一致，保持不变，不需要再次输出
+1: 基本符合 - 需求与基准SRS基本一致，可以保持不变或轻微优化
0: 部分符合 - 需求与基准SRS部分一致，需要改进以提升符合度
-1: 存在偏差 - 需求与基准SRS存在偏差，需要较大改进以消除偏差
-2: 明显冲突 - 需求与基准SRS明显冲突，需要重新设计以解决冲突

输出格式（TSV格式）：
必须使用 TSV（制表符分隔值）格式输出结果。第一行必须是表头，后续每行包含一条需求的评分结果。

TSV 格式必须为：
```
需求ID	理由	评分
REQ-001	响应时间100毫秒；基准SRS规定100毫秒	+2
REQ-002	响应时间50毫秒；基准SRS规定100毫秒（优于基准）	+1
REQ-003	响应时间200毫秒；基准SRS规定100毫秒，非200毫秒	-1
REQ-004	功能X启用；基准SRS要求功能X	+2
REQ-005	功能Y禁用；基准SRS要求功能Y启用	-2
```

**重要**：评分列（第3列）必须只包含以下数值之一：+2, +1, 0, -1, 或 -2。不要在此列填写"评分"或其他文字。

要求：
- 使用**制表符**作为列分隔符（不要使用逗号、空格或竖线）
- 第一行必须是表头：`需求ID	理由	评分`（列之间用制表符分隔）
- 每条数据行必须包含三列，用制表符分隔：
  - 第1列：需求ID（如 REQ-001）
  - 第2列：理由（简短理由30字内，必须引用基准SRS中的具体证据，包含具体细节如时间值、组件名称或具体要求。避免使用"与基准SRS一致"或"与基准SRS存在偏差"等泛化表述。应说明具体事实，例如"响应时间50毫秒；基准SRS规定100毫秒（优于基准）"或"功能X要求；基准SRS要求功能X"。如果需求参数优于基准，应注明，例如"响应时间50毫秒；基准SRS规定100毫秒（优于基准）"）
  - 第3列：评分（必须是以下数值之一：+2, +1, 0, -1, -2，只能是数值，不能是"评分"文字。**注意：参数优于基准SRS的需求（如更快的响应时间、更高的性能等）应给予正向评分（+1或+2），而不是0分或负分**）
- 理由列可以包含逗号、分号等任何标点符号 - 只有制表符用作分隔符
- 必须覆盖所有需求，不能遗漏
- 不要在 TSV 格式之外包含任何额外的文字说明、空行或注释
